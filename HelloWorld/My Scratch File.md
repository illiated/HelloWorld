
Problem Solving Principles based on the video: https://www.youtube.com/watch?v=COuz_xS18l0

Turn the issue into a goal to be solved, rather than a complaint:

	Write down: "I expected this to happen, but this happened instead."
		This will turn the issue into a goal to be solved, rather than a complaint

Turn the goal into questions small enough to start answering as soon as possible:

	Examples: "When the code hits this line does the program keep running or stop?"
			  "Which variable is involved in the issue and whats sitting in it at the time of the issue?"
			  "What is running first, and what is running second? Is the order of operations correct?"

Veryfy by predicting the next issue or break. This can be done all the time in fact: Breaking things on purpose and predicting the outcome to understand it better.

	Once I research and find a potention answer to the issue use it to make a prediction about what will happen next.
	make a prediction out loud or in notes beofre I run anything else.
		"If what i understand is correct then when I move this line above that one this will happen or it should break in this specific way."
	Then go ahead and run it on purpose to see if it breaks or acts as predicted. If it does then I can be more confident in my understanding of the issue. If it doesn't then I need to go back and research more.
	If it does not then go back to the first priciple and begin the cycle again because you just found the next break.

The Loop:

	'Break' 'Name it' 'Question it' 'Predict it' 'Test it' 'Repeat'
	The speed of this loop is the learning speed. The faster you can go through this loop the faster you will learn and understand the issue at hand.



Learning Principles:
	
When learning something new, if I am feeling kind of disinterested and flat. Always manufacture some breaks yourself so you always make predictions and learn form them.

	Close it and rebuild the last 10minutes form sctatch. You will fall on your face immediatly. This is start of an learning opportunity.

	Change the requirements of what the tutorial asks you yo build. Make it do something the tutorials does not ask you to do. Go an inch or two off the path and see what happens. You will learn more from the mistakes you make than the things you do right.

	Try to explain it to someone who has no understranding of the topic. If you can explain it to them in a way that they understand then you understand it. If you cannot explain it to them then you do not understand it and need to go back and learn more.
